# 완성본 출력 기준

아래 양식을 완성본 PDF의 출력 기준으로 사용한다.

## 배치

- 문제와 손풀이가 함께 있는 원본을 위에 배치하고, 그 아래에 `손풀이 참고` 박스를 둔다.
- 문항과의 대응이 확인된 세로로 긴 원본은 손풀이 중간의 빈 줄에서 위아래 두 부분으로 나눈다. 문제와 앞부분은 왼쪽, 이어지는 손풀이는 오른쪽에 세로로 길게 배치해 왼쪽부터 읽게 한다. 각 부분은 두 열에 맞춰 가능한 한 크게 표시한다.
- 원본이 짧거나 문제·수식·그림·필기를 온전히 보존하며 나눌 자리가 없으면 한 덩어리로 위에 놓는다. 손풀이가 없는 문항은 문제 원본을 위에 놓고 아래에서 풀이를 시작한다.
- 원본 위의 문제 본문은 자르지 않는다. 바깥 빈 여백만 출력 사본에서 줄이며 업로드 원본은 바꾸지 않는다.
- 짧은 답이나 희미한 획인지 구별하기 어려운 표시는 남긴다. 이때는 여백이 일부 남더라도 원문 보존을 우선한다. 추가 첨부가 있으면 자동으로 여백을 자르지 않는다.
- 문제만 있는 앞쪽 묶음이나 동일 원본을 중복해서 넣지 않는다.
- 참고 박스는 흰 바탕, 얇은 회색 테두리, 둥근 모서리, 올리브색 제목을 쓴다.
- 완성본은 머리글을 비우고, 원본 문항 번호가 확인된 경우 원본 위 왼쪽에 표시한다. 참고 박스는 파란색 A·B·C 표시와 왼쪽에 맞춘 수식으로 풀이를 바로 시작한다.
- `확인 필요`는 작업 화면의 검토에 사용한다. PDF 미리보기와 내보내기에는 표시하지 않는다.
- 본문은 한컴바탕 11.2bp, 줄 간격 18.2bp이며 수식은 LaTeX와 Cambria Math로 조판한다. 풀이 단계와 다음 단계 사이에 빈 줄 한 줄을 두고, 식·설명·표 사이에도 읽기 편한 간격을 둔다.
- 큰 글씨는 자주 사용하지 않는다. 중요한 판단만 굵기·밑줄로 절제해 표시한다.
- 완성 PDF는 한 쪽에 한 문항으로 구성한다. 해당 문항의 원본과 참고를 같은 쪽에 두며, 길면 중복 설명과 불필요한 여백을 먼저 줄인다. 기본 내보내기에서 읽을 수 있는 크기로 한 쪽에 담기 어려운 보강은 다음 쪽으로 이어진다.

## 설명과 그래프

- 선생님이 쓴 미지수, 원래 단계 ID, 순서와 분기를 보존한다.
- 새 풀이와 손풀이 보강 모두 도형·그래프가 핵심 판단을 전달하도록 작성한다. 문제 조건이나 해당 단계까지 확인한 식으로 그릴 수 있으면 원문에 그림이 없는 단계에도 넣는다.
- 실제로 비교하는 선분·각·거리·접점·경계를 직접 표시한다. 수직선에는 구간의 양 끝과 포함 여부를 표시하고, 길이·높이·범위는 해당 선이나 영역 가까이에 적는다.
- 핵심 판단을 담은 그림은 넓게 배치하고 바로 근처에 이어지는 식을 둔다. 보조 그림은 작게 둘 수 있다. 순수 계산은 짧은 식으로 정리한다. 검토할 때는 그림으로 보여 줄 수 있는 핵심 관계가 본문이나 표에만 남아 있는지 확인한다.
- 그래프의 식과 라벨은 축·곡선·직선·보조선·점·다른 라벨과 겹치지 않게 배치한다. 그림 안에 자리가 부족하면 그림 바깥 여백을 쓴다.
- 새 그래프 안에는 수식, 점·축 이름, 숫자와 수학 기호만 둔다. 한글 설명은 그래프 바로 옆이나 아래 풀이에 쓴다.
- 생략된 판단만 보충한다. 그래프·표·수식에 있는 같은 내용을 본문으로 다시 늘어놓지 않는다.
- 분수는 분자와 분모를 가로 분수선 위아래에 조판한다. 정적분에 원시함수의 끝값을 대입하는 식은 LaTeX로 `\left[F(x)\right]_{a}^{b}`처럼 쓰고 대괄호 오른쪽 아래에 아래끝, 위에 위끝을 둔다. 대칭이나 넓이로 값을 구하는 풀이에는 그 근거를 보여 준다.
- 교점 수를 셀 때는 필요한 높이의 직선과 실제 교점을 표시한다. 개수나 접점을 세는 이유를 밝혀야 하면 그림 가까운 풀이에 짧게 적는다. 접점은 한 점으로 센다.
- 그림에 없는 경우의 이유만 한 문장이나 한 줄 식으로 덧붙인다. 답은 짧은 식으로 남긴다.
- x값·y값을 읽는 점에는 보조선, 이동·대칭을 비교하는 곳에는 짧은 화살표, 넓이를 읽는 곳에는 경계와 음영을 직접 넣는다. 다음 식으로 넘어가는 데 필요한 이유만 그림 가까이에 남긴다.
- 정적분으로 넓이를 나타낼 때는 각 음영에 대응하는 정적분식과 그 영역을 향하는 짧은 화살표를 둔다. 계산한 넓이 값은 풀이 수식에 쓴다. 원래 손풀이에서 원시함수의 끝값 차이로 직접 비교한 경우 그 비교식을 보존한다.
- 표는 서로 다른 조건을 열로 비교해야 이해가 쉬워질 때만 쓴다. 도함수의 부호를 그림이나 한 줄로 읽을 수 있으면 증감표를 생략한다.
- `최댓값·최솟값`, `x값·y값`, `증가하는 구간·감소하는 구간`처럼 익숙한 표현을 쓴다. 값에 도달하지 않는 경우에는 도달하지 않는다는 사실을 풀어서 설명한다.
- `세 단조구간` 같은 용어와 집합·원소·교집합·합집합 등으로 설명하는 방식은 쓰지 않는다. 가능한 값, 또는·그리고, 각각 확인할 조건을 직접 적는다. 원본에 있는 조건은 보존한다.
- y=0은 x축, 다른 높이는 직선의 식을 적는다. 다른 직선을 x축이라고 부르지 않는다.
- 판독이 흐린 숫자는 불확실성을 유지한다. 수학적으로 계산한 값과 불명확한 원문 전사를 구별하고, 불명확한 필기를 계산 오류라고 단정하지 않는다.

## 적용 범위와 확인

새 작업은 `baeksin-v16` 템플릿과 `stacked-reference` 원본 배치를 저장한다. 파일만 등록하거나 출력 PDF를 수작업으로 고쳐 적용한 것처럼 처리하지 않는다.

연구실이 연결된 API로 문항을 읽고 해설·그래프 구성을 작성한다. 그래프는 저장된 레시피를 연구실에서 렌더링하고 기준 템플릿에 조판한다. 한 번에 최대 4문항씩 검토하며, 현재 묶음의 검토를 마치고 다음 묶음을 명시적으로 시작한다.

단일 결과 문항과 동일 바이트의 문제·손풀이 이미지 한 장은 확실한 대응으로 처리한다. 다문항 PDF의 자동 대응은 별도 근거 없이 추정하지 않는다. 기존 작업을 사용자의 검토 없이 수정하거나 검토 완료로 바꾸지 않는다.

검증은 새 이미지 업로드 → 앱의 풀이 작성 → PDF 내보내기를 거치고, 생성 결과에 수동 해설을 끼워 넣지 않은 상태에서 수학·원문 순서·전체 페이지의 렌더링을 확인한다.

## 사용자 지시 갱신

연구실 작업 중 사용자가 지정한 풀이·그래프·조판·작업 진행 기준을 이 문서와 실제 작성에 쓰는 제작 기준에 반영한다. 같은 항목에 새 지시가 있으면 최신 지시로 갱신한다. 특정 문항이나 출력본에만 요청한 수정은 해당 작업에 적용한다.
