# 손해설 제작 프로젝트 v1

2026-11-11 사용자 지시와 아래 정본의 학생용 작성 규칙을 풀이 연구실에 적용한다.
우선순위는 이 프로젝트의 직접 지시, 해설 생성 금지 항목, 학생용 수학·편집 품질, 변형 해설의 서술 규약, 2022 교과 범위, 그래프 작성법 순서다. 이 순서는 아래에 옮긴 작성 규칙에도 적용한다. 외부 프로젝트의 출력 스키마·변형 문항 생성·폴더 및 인계 절차는 적용 대상에서 제외한다. 추가 요청은 문항 범위와 보충할 부분을 정하며 금지항목과 수학 조건을 바꾸지 않는다.

## 문제와 손풀이

- 문제 PDF나 이미지에서 문항 번호·소문항 번호·조건·보기와 ①~⑤를 인쇄된 순서대로 읽는다. 선택된 문항만 작성한다. 이미지에 있는 학생 필기나 메모에서 새로운 문제 조건을 가져오지 않는다.
- 손풀이를 받은 문항은 원래 미지수·핵심 발상·단계 순서·경우의 분기를 보존한다. 읽은 문자를 수학적으로 그럴듯한 값으로 고치지 않는다. 단계에 필요한 이유만 덧붙인다. 손풀이를 받지 않은 문항은 해당 과목의 교과서에서 따라 할 수 있는 표준 풀이를 쓴다.
- 원래 해설이나 정답 표시와 별개로 문제 조건에서 답과 계산을 직접 확인한다. 확인한 계산이 읽을 수 있는 손풀이와 다르면 손풀이를 그대로 두고 해당 문항 끝의 확인 항목에 어느 식이나 답이 어떻게 다른지 적는다. 원본 판독이 애매하면 위치와 확인이 필요한 기호·조건을 적고, 판독과 계산에서 얻은 값을 구별한다. 조건이 불명확하면 추측한 답을 확정하지 않는다. 차이와 판독 문제만 [확인 필요]에 적는다. 내부 검산 결과는 checks에만 남긴다.

## 학생용 해설

- 각 문항은 문제 번호, 정답, 핵심 한 줄, 번호를 붙인 단계, 해당할 때만 [확인 필요] 순서다. 정답에는 문제에서 요구한 값을 적고, 객관식은 그 값에 해당하는 인쇄된 ①~⑤를 함께 쓴다. 소문항의 모든 답과 풀이를 같은 순서로 싣는다. firstDecision에는 어떤 조건에서 풀이를 시작할지 한 문장으로 쓴다.
- 각 단계에 판단 하나와 그 판단에 필요한 이유를 쓴다. 조건을 해석하고 식을 세우는 과정과 계산을 구별한다. 원래 손풀이의 한 단계에 여러 식이 있으면 그 단계 안에서 문장이나 식을 나누고 원래 단계 순서를 유지한다. 필요 조건, 양변을 나누는 근거, 끝점·등호, 예외, 중간식, 경우별 합을 빠뜨리지 않는다. 단순 대입과 반복 계산은 묶는다. 마지막 계산에서 문제에서 요구한 값을 직접 얻는다.
- 경우 구분은 평문으로 '경우 1.'처럼 쓴다. 원문자는 선택지에만 사용한다. 경우를 나눈 기준과 해당 범위를 밝힌다. 해가 여러 갈래이면 '또는'으로 잇는다. ㄱ·ㄴ·ㄷ의 각 판단에 이유를 적는다.
- 문체는 '-이다/-한다'로 쓴다. 청유형과 감탄, '먼저 구한다', '다음을 얻는다' 같은 절차 안내 대신 '…이므로 …이다'로 논리를 직접 쓴다. '검산', '원문 오류', '검토했음', 'AI', 판독·작업·편집 기록 등 제작 과정은 학생용 풀이 본문·제목·캡션에서 뺀다. 수학적으로 필요한 조건 확인은 풀이로 남긴다.
- 변수·값·개수·좌표·식은 본문에서 \(...\)로 감싼 LaTeX로 쓴다. 단계·문항 번호와 소문항 표지는 평문이다. 별도 수식 필드에는 바깥 구분자를 빼고 LaTeX만 쓴다. 한국어 단서와 '이므로', '또는'은 수식 밖에 쓴다. 빈 \text{}, 배치용 \quad, 유니코드 첨자, 곱셈을 뜻하는 평문 x 또는 *를 쓰지 않는다. 곱셈 기호가 필요하면 \times, 팩토리얼 뒤 등호는 4!{}=24, 조합은 {}_{n}C_{r}로 쓴다. 문제에 정의된 표기가 있으면 그대로 쓴다. 방정식과 해를 쉼표로 나열하지 않는다. 다시 참조하는 등식에만 ㉠, ㉡을 식 바깥에 붙인다. aligned는 같은 식의 변형, cases는 구간별 함수나 연립방정식에 쓴다.
- 기호는 처음 사용할 때 정의하고 문항 끝까지 같은 뜻으로 쓴다. 비교하는 대상과 순서를 명시한다. 실제 점 이름만 \mathrm{A}처럼 로마체로 쓰고, 원래 대소문자·첨자·프라임을 유지한다. 점과 변수 이름을 혼용하지 않는다. 보조 문자는 꼭 필요할 때만 고르고 원문에 없는 u, v는 새로 도입하지 않는다. 치환·보조변수는 t, 각은 \theta, 상수·정수는 a, b, c, d, k, m, n, p, q 중 원래 문자와 겹치지 않게 고른다.
- '함숫값', '꼭짓점', '극댓값·극솟값', '최댓값·최솟값', '증가하는 구간·감소하는 구간', '아래로 볼록·위로 볼록' 등 고등학교 표현을 쓴다. 극값과 전체나 주어진 구간의 최댓값·최솟값을 구별한다. 미적1 보충에서 집합·원소·교집합·합집합을 별도 풀이 틀로 끌어오지 않고 조건을 식이나 문장으로 바로 쓴다. '단조구간', '이차인수', '판정 수평선', '상한·하한', '가로좌표·세로좌표'는 쓰지 않는다. 'x값·y값'을 사용하며 직선 y=0은 x축, y=c는 식으로 명시한다. 도달하지 않는 값에 최댓값·최솟값이 있다고 쓰지 않는다. 인수는 실제 식이나 '인수를 2개 가진다'처럼 뜻을 풀어 쓴다.
- 교과 파일의 허용 개념과 경계를 지킨다. 기하 문제 외에는 벡터·내적·벡터방정식·방향벡터 논증을 쓰지 않는다. 대학 정리나 낯선 기호로 우회하지 않는다. 실수 조건은 'x는 실수'처럼 쓰고 정수부분에 [t]를 쓰지 않는다. 필요한 계산은 외부 답지 검색 없이 주어진 문제에서 확인한다.
- 해당하는 조건을 빠뜨리지 않는다. 방정식은 분모가 0인 값과 무연근, 함수는 정의역과 역함수 조건, 로그·삼각함수는 진수 조건과 각 범위, 수열은 처음 항과 첨자, 미분은 미분가능성과 닫힌 구간의 끝점, 적분은 시작·끝과 부호, 경우와 확률은 순서·중복·누락과 조건이 되는 사건의 확률을 확인한다.
- 정적분에서 원시함수에 끝값을 대입할 때는 \left[F(x)\right]_{a}^{b}처럼 대괄호를 쓴다. 아래끝은 대괄호 오른쪽 아래에, 위끝은 오른쪽 위에 둔다. 대칭이나 넓이로 값을 바로 구할 수 있으면 그 근거를 그림이나 식으로 보여 준다.

## 그림이 풀이에 필요할 때

- 교점 수·대칭·부호·개형·넓이·경계·보조선이 판단에 쓰일 때만 그린다. 순수 계산에 장식 그림을 붙이지 않는다. 원래 그림은 손대지 않고 보충 그림은 그 관계를 사용하는 단계에 둔다.
- 개형을 정하는 데 필요한 조건과 성질을 먼저 밝힌 뒤, 그 그림을 읽는 첫 설명과 상세 계산 전에 놓는다. 현재까지 확정된 식과 점만 표시한다. 이후에 얻는 좌표·수치·결론을 앞 그림에서 공개하지 않는다. 계산 전 개형을 그릴 수 없으면 이미 확정한 관계를 설명하고, 근거 없는 수치나 모양을 만들지 않는다.
- 점·선·영역의 무엇을 읽어서 어느 식을 세우는지 짧게 잇는다. 필요한 축만 표시하고 라벨은 대응하는 점·선 가까이에 둔다. 본문과 그림의 점·함수 이름·정의역·교점 수·접함·음영을 일치시킨다. 정적분의 부호와 넓이, 접점 하나와 중복도, 극한의 높이와 함숫값을 구별한다.
- 새 그래프 안에는 수식, 점·축 이름, 숫자와 수학 기호만 둔다. 한글 설명은 그래프 바로 옆이나 아래 풀이에 쓴다. 식과 라벨은 축·곡선·직선·보조선·점·다른 라벨과 겹치지 않는 빈 자리에 둔다.
- 열린 점과 닫힌 점은 등호와 맞춘다. 곡선은 불연속을 가로질러 이어 그리지 않고 음영 끝을 정의역 끝으로 보이게 자르지 않는다. 비교하는 범위를 잘라 교점을 숨기지 않는다. 도형의 길이·각도·닮음은 외형이나 임의 축척으로 증명하지 않는다.
- 새 그림은 코드 실행 없이 `figure_recipe_v1` 데이터로만 작성한다. 근거가 있는 곡선식·점·보조선·정의역·음영·라벨을 해당 단계의 `figureRecipe`에 담는다. 함수 라벨은 식 또는 원래 함수명을 쓴다. 내부 작도값은 라벨에 공개하지 않는다. 화살표는 실제 이동이나 대응이 필요할 때만 쓴다. 학생이 읽어야 할 것을 그림에 직접 표시하고 긴 설명은 풀이에 둔다.
- 점과 축의 라벨은 실제 대상에 연결하고 열린 점과 닫힌 점을 구별한다. 곡선과 x축 사이 영역은 채움 구간을 쓸 수 있다. 두 곡선 사이 영역은 두 경계를 계산한 닫힌 경로로 채운다. 화면 범위와 라벨 방향을 조정해 식이 선이나 점과 겹치지 않게 한다.

## 연구실 작업과 PDF

- 문제 판독, 손풀이 보강과 새 그래프의 구성은 연구실에 연결된 OpenAI API를 사용한다. 저장된 레시피로 그래프를 그리고 LaTeX로 PDF를 조판한다.
- 완성 PDF는 한 쪽에 한 문항을 배치한다. 대응이 확인된 세로로 긴 원본은 손풀이 중간의 빈 줄에서 나눈다. 문제와 풀이 앞부분을 왼쪽, 이어지는 풀이를 오른쪽에 놓고, 두 부분 아래에 해당 문항의 `손풀이 참고`를 넣는다. 원본이 짧거나 내용 사이에 나눌 자리가 없으면 원본 전체를 위에 놓는다. 문제 본문과 필기는 온전히 유지한다.
- 풀이 단계 사이에 본문 한 줄 높이의 간격을 둔다. 길면 반복 설명과 비어 있는 여백부터 줄인다. 기본 내보내기에서 읽을 수 있는 크기로 한 쪽에 담기 어려운 보강은 다음 쪽으로 이어진다.
- 4문항씩 보강하고, 현재 묶음을 사용자에게 보여 준 뒤 명시적인 허용을 받고 다음 묶음을 시작한다.
